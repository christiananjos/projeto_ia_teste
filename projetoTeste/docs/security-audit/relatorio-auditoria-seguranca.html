ISSUES PARA O GITHUB

--- ISSUE 1 ---
## [Segurança] Startup aceita chave JWT conhecida (chave de teste versionada)

**Labels sugeridas:** `security`, `severity:low`

### Problema
A validação de `JwtOptions` em `src/API/Configuracao/AutenticacaoExtensions.cs` só verifica se a chave
existe e tem pelo menos 32 bytes. Uma chave pública, versionada no repositório, passa nessa validação:
por exemplo, a chave dos testes de integração. Se ela for configurada em um ambiente real (copiada de
`TokenJwt.cs` para user-secrets ou variável de ambiente), qualquer pessoa com acesso ao código consegue
assinar um JWT com `role: Admin` e executar todas as operações de escrita.

### Evidência
`src/API/Configuracao/AutenticacaoExtensions.cs:20-26`
```csharp
services.AddOptions<JwtOptions>()
    .Bind(configuration.GetSection(JwtOptions.Secao))
    .ValidateDataAnnotations()
    .Validate(
        o => o.ChaveAssinatura is not null && Encoding.UTF8.GetByteCount(o.ChaveAssinatura) >= JwtOptions.TamanhoMinimoChaveBytes,
        $"Autenticacao:Jwt:ChaveAssinatura deve ter pelo menos {JwtOptions.TamanhoMinimoChaveBytes} bytes.")
    .ValidateOnStart();
```
`src/Tests/Catalogo.IntegrationTests/Infra/TokenJwt.cs:15`
```csharp
public const string Chave = "chave-de-teste-do-catalogo-com-mais-de-32-bytes";
```

### Quando é explorável
Só quando um operador configura uma chave conhecida fora do ambiente de testes. Hoje nenhum arquivo
versionado define a chave de produção.

### Impacto
Forjar tokens `Admin`, ou seja, criar, alterar e remover qualquer categoria ou produto.

### Sugestão de correção
- Fora do ambiente de testes, rejeitar no startup uma lista de chaves conhecidas (a chave de teste e
  placeholders da documentação), por exemplo com `.Validate(...)` e o `IHostEnvironment`.
- Documentar em `docs/api/testes-api.md` a geração de uma chave aleatória
  (ex.: `openssl rand -base64 64`).
- Opcional: quando o provedor de identidade for definido, migrar para chave assimétrica via JWKS.

### Critérios de aceite
- [ ] Com `ASPNETCORE_ENVIRONMENT` diferente do ambiente de testes, a API não sobe usando a chave de `TokenJwt.Chave`.
- [ ] Os testes de integração continuam subindo a API com a chave de teste.
- [ ] Há um teste automatizado para a rejeição da chave conhecida.
- [ ] A documentação mostra como gerar uma chave aleatória forte.
